AutoJudge Evaluation Engine — Distributed System Workflow & Quick Start

================================================================================
QUICK START: HOW TO RUN THE SYSTEM & EXPECTED RESULTS
================================================================================
NOTE : Run this command first if the .jar cannot be found
  - mvn clean package
  
Prerequisites:
  - RabbitMQ broker running on localhost:5672 (or via RABBITMQ_HOST environment variable).
  - Docker daemon active (for containerized evaluation sandboxing).
  - Production JAR compiled via: `mvn clean package` -> `target/evaluation_engine-1.0-SNAPSHOT.jar`

Step 1: Start the Result Worker (Report Aggregator)
  Run Command:
    java -jar target/evaluation_engine-1.0-SNAPSHOT.jar result-worker results.xlsx
  
  Where to expect results:
    - Target Output File: `results.xlsx` (or the path passed as the 2nd argument).
    - Output Format: Styled Microsoft Excel spreadsheet containing student evaluation outcomes.
    - Columns: [Submission ID | Student ID | Assignment ID | Batch ID | Verdict | Score (%) | Passed Tests | Total Tests]

Step 2: Start Evaluation Worker Node(s)
  Run Command:
    java -jar target/evaluation_engine-1.0-SNAPSHOT.jar worker
  
  Notes:
    - Can run multiple worker processes in parallel across machines/containers.
    - Workers listen continuously on RabbitMQ `evaluation.queue` with prefetch QoS=1.

Step 3: Publish Evaluation Jobs (Producer) & Optional Plagiarism Checking
  Standard Run Command (No Plagiarism):
    java -jar target/evaluation_engine-1.0-SNAPSHOT.jar producer <assignment-path>

  Run Command with Plagiarism Checking Enabled:
    java -jar target/evaluation_engine-1.0-SNAPSHOT.jar producer <assignment-path> --plagiarism
  
  Examples:
    java -jar target/evaluation_engine-1.0-SNAPSHOT.jar producer assignments/assignment-1
    java -jar target/evaluation_engine-1.0-SNAPSHOT.jar producer assignments/assignment-1 --plagiarism
  
  Behavior:
    - Scans `<assignment-path>/submissions/` for student folders.
    - Auto-detects programming language dynamically from student source files (e.g. C++, Java).
    - If `--plagiarism` flag is passed, triggers `PipelineOrchestrator.processPlagiarismStage()` for the assignment.
    - Generates a unique `batchId` for the run.
    - Pushes `EvaluationJob` messages into RabbitMQ `evaluation.queue`.
    - Once workers evaluate all jobs in the batch, `results.xlsx` is automatically generated by the Result Worker.

Step 4: Optional Plagiarism Checking (Pipeline Stage & Results Destination)
  Execution via PipelineOrchestrator:
    - Plagiarism checking is an optional stage driven by `PipelineOrchestrator`.
    - Enable via CLI `--plagiarism` flag or setting `plagiarismEnabled = true` in API/request.
    - If disabled, the plagiarism stage is completely bypassed.
  
  Where to expect plagiarism results:
    - Console & System Logs: Structured similarity logging via SLF4J (`autojudge.PlagiarismDetection.*`).
    - Domain Return Object: `PlagiarismReport` containing a list of `SimilarityPair` objects (`studentA`, `studentB`, similarity %).
    - REST / UI Integration: In API mode, `PlagiarismReport` is returned in the API response or attached to assignment run metadata for instructor review.

================================================================================
1. INITIATING COMMANDS & CLI MODES
================================================================================
A. Producer Mode (Distributed Job Publishing):
   java -jar target/evaluation_engine-1.0-SNAPSHOT.jar producer <assignment-path> [--plagiarism]
   - Scans <assignment-path>/submissions/ directory structure.
   - Auto-detects programming language from student source files via SubmissionScanner.
   - If `--plagiarism` is enabled, runs language-aware JPlag analysis on student submissions.
   - Creates serializable EvaluationJob objects with unique batchId.
   - Publishes jobs to RabbitMQ evaluation.exchange (evaluation.queue).

B. Worker Mode (Distributed Evaluation Consumer):
   java -jar target/evaluation_engine-1.0-SNAPSHOT.jar worker
   - Long-running consumer listening on RabbitMQ evaluation.queue with prefetch QoS=1.
   - Delegates EvaluationJob execution to EvaluationEngine and publishes SubmissionResult to result.queue.
   - On error: publishes INTERNAL_ERROR result and NACKs message without requeue.

C. Result Worker Mode (Aggregation & Reporting):
   java -jar target/evaluation_engine-1.0-SNAPSHOT.jar result-worker [reportOutputPath] [expectedCount]
   - Consumes SubmissionResult objects from result.queue.
   - Generates formatted Excel report (results.xlsx) using ExcelGenerator when batch results complete.

D. Direct Local Mode (Single Submission CLI Execution):
   java -jar target/evaluation_engine-1.0-SNAPSHOT.jar <submissionPath> <inputDirectory> <outputDirectory> <configFile> <weightsFile>

E. Pipeline Mode (Optional Plagiarism Stage):
   - Invoked via `PipelineOrchestrator.processPlagiarismStage(assignmentId, assignmentPath, language, plagiarismEnabled)`.
   - Supports dynamic language mapping ("cpp", "c++", "java").
   - Unsupported languages log a warning and skip gracefully without failing evaluation.

================================================================================
2. MANDATORY ASSIGNMENT DIRECTORY STRUCTURE
================================================================================
<assignment-path>/
  ├── config.json       : Assignment limits & profile config
  ├── weights.json      : Test case weight mappings
  ├── input/            : Test case input files
  ├── expected/         : Expected output files
  └── submissions/      : Student submission folders
      └── <studentId>/  : Individual student submission directory

================================================================================
3. STEP-BY-STEP EVALUATION WORKFLOW
================================================================================
Step 1: Job Consumption & Path Resolution (EvaluationEngine)
  - Worker receives EvaluationJob (containing assignmentPath & submissionPath).
  - EvaluationEngine resolves internal paths relative to assignment root:
    * inputDirectory  : <assignmentPath>/input
    * outputDirectory : <assignmentPath>/expected
    * configFile      : <assignmentPath>/config.json
    * weightsFile     : <assignmentPath>/weights.json
  - Loads configuration, pairs test cases, and creates EvaluationContext.

Step 2: Container Provisioning & Security Hardening
  - Log: `[DockerRunner.java] Step 1: Provisioning & starting Docker container...`
  - Create isolated container using universal image (`auto-judge-container:v1.0`):
    * Memory limit: 256MB / 512MB
    * CPU quota: 1.0 NanoCPU
    * Network Mode: "none"
    * PID Limit: 100

Step 3: Submission Copy & In-Container Compilation
  - Copy student source directory to container workspace (/workspace).
  - Auto-detect language at runtime via SubmissionScanner.
  - Compile using CompileCommandBuilder with timeout wrapper (`timeout -k 1s 30s <command>`).
  - If compilation fails, return COMPILATION_ERROR for test cases.

Step 4: Iterative Test Case Execution & Security Monitoring
  - Execute test cases with GNU timeout wrapper (`timeout -k 1s <limit>s <script>`).
  - Track pre/post execution file snapshots. Unrecognized file creation triggers
    immediate container teardown and MALICIOUS_CODE verdict (score = 0.0).

Step 5: Scoring, Result Publishing & Failure Resilience
  - OutputComparator checks student output against expected output.
  - Calculate weighted score (0.0 to 100.0).
  - Publish SubmissionResult to RabbitMQ result.exchange (result.queue).
  - Acknowledge (ACK) original evaluation message in RabbitMQ.
  - On failure in worker/evaluator: NACK without requeue (`basicNack(false, false)`) and publish `INTERNAL_ERROR` verdict.

Step 6: Optional Plagiarism Analysis Stage (PipelineOrchestrator & JPlag)
  - PipelineOrchestrator checks `plagiarismEnabled` flag.
  - If `false`: bypasses plagiarism subsystem completely (no JPlag calls).
  - If `true`: triggers `PlagiarismAnalysisService` -> `JPlagDetector` -> JPlag 5.1.0 engine.
  - Dynamically resolves language module (`CPPLanguage`, `JavaLanguage`).
  - JPlag tokenizes student submissions under `<assignmentPath>/submissions/`.
  - Converts JPlag comparisons into domain `PlagiarismReport` containing `SimilarityPair` entries.

================================================================================
4. PLAGIARISM SUBSYSTEM ARCHITECTURE & BOUNDARIES
================================================================================
- Single Maven Module: All plagiarism classes reside in `autojudge.PlagiarismDetection.*`.
- Architecture Boundary: Evaluation core engine (`autojudge.CoreEvaluation.*`) has ZERO direct dependencies on JPlag or plagiarism packages.
- Adapter Pattern: `JPlagDetector` encapsulates all JPlag API calls (`de.jplag.*`) preventing JPlag types from leaking into application models.
- Service Entry Point: `PlagiarismAnalysisService` coordinates analysis requests for the pipeline.
